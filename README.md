🧪 Trello QA Project

Тестовый проект для Trello REST API: создание, изменение, архивирование и удаление досок, списков, карточек и чек-листов — с изоляцией и автоочисткой тестовых данных.

✅ Что тестируется
🗂️ Доски — создание, получение, удаление
📋 Списки — создание внутри доски
🃏 Карточки — создание, обновление, архивирование
☑️ Чек-листы — создание чек-листа и пунктов в нём

Каждый тест работает с собственной изолированной иерархией: доска → список → карточка. Доска создаётся с уникальным именем (через Faker) и удаляется по завершении теста — никакого мусора в рабочем пространстве Trello между прогонами.

⚙️ Стек
Инструмент	Роль
🐍 Python	язык тестов
✅ Pytest	тест-раннер
🌐 requests	HTTP-клиент к Trello API
📊 Allure	пошаговая трассировка запросов и вложения в отчёт
🎲 Faker	генерация уникальных тестовых данных
🔐 python-dotenv	хранение ключей вне кода
📁 Структура

🚀 Как запустить

1. Получить доступ к Trello API

Получить API-ключ: trello.com/app-key
На той же странице сгенерировать токен для своего аккаунта

2. Настроить окружение

bash
git clone https://github.com/Nikolay-Potapov-QA/Trello-qa-project.git
cd Trello-qa-project
pip install -r requirements.txt
cp .env.example .env

Заполнить .env:

TRELLO_API_KEY=ваш_ключ
TRELLO_TOKEN=ваш_токен

3. Запустить тесты

bash
pytest -v                              # все тесты
pytest -v --alluredir=allure-results   # с отчётом Allure
allure serve allure-results
🔐 Безопасность тестовых данных

Ключ и токен никогда не попадают в отчёт или консоль в открытом виде: TrelloClient перед логированием параметров запроса в Allure маскирует оба значения (***HIDDEN***) — отчёт можно свободно показывать/публиковать, не раскрывая доступ к аккаунту.

🧹 Изоляция и очистка тестовых данных

Фикстуры выстроены в цепочку зависимостей:

test_board  →  test_list  →  test_card

Каждая доска создаётся с уникальным именем (AQA_Board<random_word>) и удаляется в teardown автоматически — падение теста не оставляет мусора в Trello.
