# README-TRELLO-API-AQA

# Trello API Test Framework

Фреймворк для тестирования Trello REST API: проверяет основные операции над досками, списками, карточками и чек-листами — создание, чтение, изменение, архивирование и удаление, с изоляцией и очисткой тестовых данных после каждого прогона.

## Что тестируется и зачем

Каждый тест работает с собственной изолированной иерархией данных: тестовая доска → список → карточка. Доска создаётся с уникальным именем (через `Faker`), а по завершении теста удаляется — это исключает накопление мусора в аккаунте и пересечение данных между параллельными или повторными прогонами.

Покрытие охватывает основной жизненный цикл сущностей Trello:
- доски (создание, получение, удаление);
- списки (создание внутри доски);
- карточки (создание, получение, обновление, архивирование);
- чек-листы на карточках (создание чек-листа и пунктов внутри него).

## Стек и инструменты

| Инструмент | Роль |
| --- | --- |
| Python | язык тестов |
| Pytest | тест-раннер |
| requests | HTTP-клиент к Trello API |
| Allure | пошаговая трассировка запросов и вложения в отчёт |
| Faker | генерация уникальных тестовых данных |
| python-dotenv | хранение ключей вне кода |

## Как запустить

### 1. Получить доступ к Trello API

1. Получить API-ключ: trello.com/app-key.
2. На той же странице сгенерировать токен для своего аккаунта.

### 2. Настроить окружение

```bash
git clone https://github.com/AQANikolay/TRELLO-API-AQA.git
cd TRELLO-API-AQA
pip install -r requirements.txt
cp .env.example .env
```

Заполнить `.env`:

```
TRELLO_API_KEY=ваш_ключ
TRELLO_TOKEN=ваш_токен
```

### 3. Запустить тесты

```bash
# Все тесты
pytest -v

# С отчётом Allure
pytest -v --alluredir=allure-results
allure serve allure-results
```

## Безопасность тестовых данных

Ключ и токен никогда не попадают в отчёт или консоль в открытом виде: `TrelloClient` перед логированием параметров запроса в Allure маскирует оба значения (`***HIDDEN***`), поэтому Allure-отчёт можно свободно показывать/публиковать, не раскрывая доступ к аккаунту.

## Изоляция и очистка тестовых данных

Фикстуры выстроены в цепочку зависимостей:

```
test_board  →  test_list  →  test_card
```

Каждая доска создаётся с уникальным именем (`AQA_Board<random_word>`) и удаляется в teardown автоматически — падение теста не оставляет мусора в рабочем пространстве Trello.
