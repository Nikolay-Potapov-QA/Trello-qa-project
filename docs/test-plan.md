Тест-план Объект тестирования: REST API Trello (боевой сервис api.trello.com, тестовый workspace/аккаунт). Цели тестирования: проверить, что операции создания, чтения, изменения и удаления досок, списков, карточек и чек-листов возвращают ожидаемые статусы и корректно отражают переданные данные. Виды тестирования: функциональное тестирование API (позитивные и негативные сценарии), smoke — на каждый пуш. Тестовое окружение: реальный Trello API с тестовым аккаунтом/workspace, каждый тест создаёт и удаляет собственные данные. Из области тестирования исключено: UI Trello, тестирование прав доступа между разными пользователями/командами, вебхуки, ограничения rate limit API. Критерии входа: валидные TRELLO_API_KEY и TRELLO_TOKEN в .env, доступен api.trello.com. Критерии выхода: все тест-кейсы по CRUD-операциям над доской/списком/карточкой зелёные, отчёт Allure сформирован без ошибок инфраструктуры. Риски: Тесты зависят от доступности внешнего сервиса (api.trello.com) - не изолированы моком, при сбое сервиса тесты падают независимо от качества кода. Возможные ограничения по частоте запросов (rate limits) при частых прогонах в CI.
